# ADR-0001 — One image of the TLA+ tool family, cited by digest, with two ways in

**Status:** Accepted · 2026.11.15
**Chosen by:** the custodian chose the idea, in the session's third prompt: the same tools locally and in CI,
an MCP server outside the project to pair with the `writing-tla-specs-and-proofs` skill, and as much of the
TLA+ family as possible, TLAPS included. The assistant chose the form: one image, two ways in.
**State:** The image is built (spike, commit `770daf2`) and is not yet published. The MCP server is not built.
**Depends on:** nothing.
**Relates to:** every other record. ADR-0002 (digests), ADR-0006 (what each way in may write), ADR-0008 (the
server).

---

## Context

TOPAK checks its specifications with TLC and proves them with TLAPS, and keeps the output as committed results
files. Its CI reruns TLC. It does not rerun the proofs, because the pinned prover is an arm64-darwin binary that
upstream no longer serves and that a runner cannot run (session record, F-2). gov-tla has the same shape, with a
third prover build (F-5).

The survey of existing TLA+ MCP servers found seven (session record, §3). None ships a container image. One,
`marco6/tlapm-mcp`, wraps TLAPS. The server built into the VS Code extension needs the editor running. Another,
by default, downloads its own `tla2tools.jar`, so it runs outside a project's pin. None of them can produce
evidence a project would commit.

## Decision

1. **One container image holds the TLA+ tool family.** A project refers to it by digest and uses it the same way
   on a laptop and in CI.
2. **It has two ways in.**
   - **The command line, for evidence.** A project's own run scripts and results generators run in the image
     unchanged.
   - **An MCP server, for working.** The same binaries, offered to an agent through tools, to pair with the
     `writing-tla-specs-and-proofs` skill.
3. **Nothing in the image is specific to one project.** TOPAK is the first project it serves and gov-tla the
   second. A need of either is met only in a form the other could use.
4. **CI-checked proofs come first** (Phases 1 and 2 of `PLAN.md`) and stand without the MCP layer, which is the
   smaller gain.
5. **Which tools are in the image is not chosen at build time.** The build arguments choose two things only:
   - the base (`BASE_IMAGE`, ADR-0003);
   - which build of each tool is fetched (ADR-0002).

   Every image built from this repository holds the whole base set: the checker, the prover with its bundled
   backends, and the runtime. Optional tools are added only as the named variants of ADR-0012, and a variant
   never removes a base tool.

## Consequences

- One digest stands for the checker, the prover and its backends together. A project cites one thing, and moves
  one pin to change any of them.
- The command line is the only way to evidence. ADR-0006 keeps the server from becoming a second one.
- "The same locally and in CI" holds for Linux and CI only, until there is a Linux arm64 `tlapm` (ADR-0003). On
  Apple Silicon the image runs under emulation, and how slow that is has not been measured.
- The image is large: 806 MB at the spike. How that splits between Isabelle, the JRE and the rest was not
  measured.

## Alternatives not taken

- **Adopt an existing server.** None ships an image or pins its tools, and only one covers TLAPS (§3).
- **Install the tools in each CI job,** as TOPAK's `tools/install-tlaps.sh` does locally. Each job would repeat
  the downloads, the prover would be whatever the tag serves that day, and a laptop and a runner would differ by
  platform.
- **Separate images for checking and proving.** Two digests to cite and to move together, for a saving the 52 MB
  prover tarball does not justify (F-6).
- **Tools chosen by build arguments,** for example a build with only TLC for a project that never proves. The
  digest of each such build would still be exact. A tag, a version number or a release's pin table would no
  longer say what is inside, though (ADR-0002 item 6). The prover, which is the reason for the image (F-2),
  would become something a build might leave out. If a TLC-only image is wanted, it reverses item 5 and needs
  its own record.
