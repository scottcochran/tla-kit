# ADR-0002 — Every tool is held to a digest, and every result names the image's digest

**Status:** Proposed · 2026.11.15
**Chosen by:** the assistant (session record, §7: "both downloads checked by `ADD --checksum`, so that a moved
upstream tag fails the build"). Open to change.
**State:** Built in part. The two downloads are checked and `tla-kit-info` prints each tool's digest. The base
image digest, the `apt` snapshot, the JSON form of `tla-kit-info` and the release workflow are Phase 1.
**Depends on:** ADR-0001.
**Relates to:** ADR-0005 (the prover's tarball), ADR-0010 (where the digest is published).

---

## Context

A results file is evidence only if a reader can tell what produced it. TOPAK pins its jar in `tools/TLA-PIN`
and its prover in `tools/TLAPS-PIN`, and its results files carry a `Prover:` line. The TLAPS release tag
`1.6.0-pre` is rolling: upstream rebuilds it under the same name. In six weeks the three projects ended up on
three prover builds (session record, F-5).

## Decision

1. **Every download is held to a sha256 at build time.** The `Dockerfile` fetches `tla2tools.jar` and the
   `tlapm` tarball with `ADD --checksum`. When upstream changes what a name serves, the build fails. That is
   intended: a new build is a decision, and the place to record it is the digest argument
   (`TLA2TOOLS_SHA256`, `TLAPM_SHA256`).
2. **The image's digest is what a project cites.** It stands for every tool inside. A project's results name it.
3. **The image reports its own contents.** `tla-kit-info`, the default command, prints each tool with the digest
   a results file would cite: the jar's sha256, the `tlapm` binary's sha256, and the backend versions. In
   Phase 1 it gains a JSON form, for the MCP server's `info` tool and for scripts.
4. **The rest of the build is fixed as well** (Phase 1):
   - the base image is referenced by digest, not by tag;
   - `apt` packages are fixed by date through Ubuntu's snapshot archive;
   - the release workflow records the published digest in the release.
5. **A digest that cannot be reproduced is not cited.** The spike image was built on a derived base through a
   mirror. Its local id, `sha256:e3699009…8834`, is not to be cited.

## Consequences

- Until item 4 is done the image is not reproducible bit for bit. A rebuild from the same `Dockerfile` may
  differ in its base layer and its `apt` packages, though not in the TLA+ tools.
- Upstream will stop serving the tarballs the digests name. Once that happens a rebuild fails until ADR-0005's
  copy exists. The published image is then the only durable form of that build.
- Moving any one tool's pin changes the image digest, and every project that cites it has to move knowingly.

## Alternatives not taken

- **Pin by version tag only.** The `1.6.0-pre` tag has served at least three builds. A tag does not identify a
  build.
- **Check digests after the build, in a test.** A test reports a mismatch after the fact. A failed build means
  the mismatched tool never reaches an image.
