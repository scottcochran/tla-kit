# ADR-0003 — The base is Ubuntu 24.04 with Temurin JRE 25, on Linux x86_64 only

**Status:** Accepted · 2026.11.15
**Chosen by:** the assistant. Ubuntu 24.04 is forced by glibc (F-8). Temurin 25 is what TOPAK's `results.yml`
sets up. Open to change.
**State:** Built. Running as a non-root user is Phase 1. The arm64 build is Phase 6.
**Depends on:** ADR-0001.
**Relates to:** ADR-0002 (the base pinned by digest), ADR-0012 (variants).

---

## Context

The `tlapm` binary now served, and its bundled `zenon` and `ls4`, need glibc 2.38 (`objdump -T`, F-8). Debian 12
has 2.36 and Ubuntu 22.04 has 2.35. Upstream publishes `tlapm` for Linux x86_64. TOPAK's script says there is no
Linux arm64 build. That was recalled and not checked against the release's asset list (session record, §8).
TOPAK's CI runs TLC on Temurin. The skill's scripts need Python with the standard library only. Project scripts
call `shasum` (perl) and `git`.

The session's machine could not pull from Docker Hub and had to add a proxy certificate. So the spike was built
with a different base, passed as a build argument.

## Decision

1. **The base is `eclipse-temurin:25-jre-noble`**: Ubuntu 24.04 with Temurin JRE 25. To it the image adds
   `python3`, `perl` and `git`, without recommended packages.
2. **The image is Linux x86_64 only** until there is a Linux arm64 `tlapm`. A second platform is a second binary
   and a second digest to pin. It is added in Phase 6, built from source, and only with a check that uses it.
3. **`BASE_IMAGE` is a build argument**, for a registry mirror or a base with a private CA. The default must build
   with plain `docker build .` on a stock machine and in GitHub Actions. The stock machine is Phase 1a's first
   check, because the default path has not been tried. GitHub Actions builds it on every pull request from
   Phase 1c (ADR-0014 item 1).
4. **The image runs as a non-root user** (Phase 1), so files it writes to a mounted project are not owned by root.

## Consequences

- On Apple Silicon the image runs under emulation, at a speed not yet measured. If emulation is slow, local proof
  work stays on the native darwin binary until the arm64 build exists. "The same locally and in CI" then holds for
  CI and Linux only.
- A future `tlapm` built against a newer glibc would force a newer base. That is a base move, and it changes the
  digest as any pin move does.
- A non-root user has to work with project mounts whose owner is another uid. That needs a check in Phase 1, on
  Linux and on Docker Desktop.

## Alternatives not taken

- **Debian 12 or Ubuntu 22.04.** Their glibc is too old (F-8).
- **A distroless or Alpine base.** `tlapm` is linked against glibc, and project scripts need a shell, perl and git.
- **A JDK instead of a JRE.** Nothing in the image compiles Java.
