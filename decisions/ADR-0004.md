# ADR-0004 — The image speaks through the variables the projects already read

**Status:** Accepted · 2026.11.15
**Chosen by:** the assistant (session record, §7: "the jar and the prover exposed through `TLA_JAR` and
`TLAPM`"). Open to change.
**State:** Built. The spike's checks 1, 3, 4 and 5 ran the skill's scripts and a project's own scripts unchanged.
**Depends on:** ADR-0001.
**Relates to:** ADR-0007 (the skill's scripts).

---

## Context

The `writing-tla-specs-and-proofs` skill's scripts, and the projects' own run scripts and prover wrappers, find the
checker through `TLA_JAR` and the prover through `TLAPM` (F-10). A project's own scripts are what make its
evidence. An image that needed those scripts changed would split each project into one version for the image and
one without it.

## Decision

1. **The image sets `TLA_JAR` and `TLAPM`** to its own jar (`/opt/tla/tla2tools.jar`) and prover
   (`/opt/tlaps/bin/tlapm`), and puts `/opt/tlaps/bin` on `PATH`, so `tlapm` and `tlapm_lsp` are commands.
2. **`tlc`, `sany` and `pcal` are thin wrappers on the jar,** each one `exec java … <class> "$@"`. The only option
   any of them adds is the garbage collector for `tlc` (`-XX:+UseParallelGC`).
3. **The working directory is `/work`.** A project is mounted there, read-only when nothing should be written.
4. **The image adds no adapter that a project has to call.** When a project's script and the image disagree, the
   fix goes in the project, in its own repository, or in the image, never in a shim between them. A pin key
   that the skill's scripts and a project's pin file name differently (F-9) is fixed in that project (Phase 2).

## Consequences

- Without Docker, a project keeps working exactly as it does now. The image changes only where the variables
  point.
- The variable names are an interface. A project or the skill that renames one breaks the image's route in, and
  the self-test (Phase 1) should exercise both.
- A script that ignores the variables and finds its own tools escapes the image's pin. That is a fault in the
  script, and is reported where the script lives.

## Alternatives not taken

- **A `tla-kit` command that wraps every project operation.** That would be a second copy of each project's run
  scripts.
- **Fixed paths written into the projects.** Those would tie each project to the image's layout.
