# ADR-0006 — The MCP server has no way of its own to write a results file

**Status:** Proposed · 2026.11.15
**Chosen by:** the assistant (`PLAN.md` rule 2). Open to change.
**State:** Planned, Phases 3 and 4. No server exists.
**Depends on:** ADR-0001 (evidence by the command line), ADR-0007 (the skill's scripts).
**Relates to:** ADR-0008 (the server), ADR-0009 (the proof tools).

---

## Context

A results file in TOPAK is evidence. It is regenerated by a generator script, compared in CI, and cited by
records. An agent working through MCP tools gets fast, partial answers: one row, one step, a sample of
behaviours. If those answers could be written as results files, a file could look like evidence while having
come from a path no one reviews.

## Decision

1. **The server writes a results file only by running a generator,** either the project's own or one of the
   skill's (`tlc_rows`, `proof_results`), with the generator's arguments and output unchanged. That file is the
   file the script writes when run from the command line.
2. **Every other tool returns working output, labelled as working output.** It is never written into the
   project. Sampling is labelled as sampling (`simulate`). A single step proved is not reported as a module
   proved.
3. **The server has no general file-writing tool.** Scratch modules (`evaluate`) and caches (`prove`) live in
   directories the server owns, outside the project.

## Consequences

- Evidence has one path, whether a person or an agent starts it. CI reviews a results file the same way whoever
  made it.
- An agent cannot turn a single passing step into a claim about a module. To make a claim, it runs the
  generator.
- The Phase 3 and Phase 4 tests have to show this as well as the tools' verdicts. Phase 4's check that
  `proof_results` through the server writes the file the script writes is one such test.

## Alternatives not taken

- **Let the server write results and label them as made through MCP.** That makes two kinds of evidence, which
  every reader would then have to tell apart.
- **A read-only server.** Running the generators would then have to happen outside the session, and an agent
  could not finish its work.
