# ADR-0009 — The proof tools follow marco6/tlapm-mcp's design, with named changes, and do not depend on it

**Status:** Accepted · 2026.11.16
**Chosen by:** the custodian (`PLAN.md` D6), on 2026.11.16, as the plan recommended: `marco6/tlapm-mcp` is a design
to follow, not a dependency. The changes in item 3 are the assistant's.
**State:** Planned, Phase 4.
**Depends on:** ADR-0005 (the one prover), ADR-0006, ADR-0008.
**Relates to:** ADR-0007 (`proof_results`, `flip_test`, `proof_sync` are the skill's scripts), ADR-0016 (the
`prove` tool's requests, processes and cache, which waits on item 5).
**Pending:** none.

---

## Context

`marco6/tlapm-mcp` (Go, MIT, one star, 22 commits, one release: `v0.0.1` of 2026.11.10) is the only server found
that wraps TLAPS. It has
two tools. `check` runs `tlapm --summary -N`. `prove` runs `--timing` with `--line N` or `--toolbox FROM TO`, and
`--nofp` when the caller turns the cache off. It parses the Toolbox protocol's blocks and returns only the
unresolved obligations, with line, status and reason.

It does not return an obligation's text. It takes `tlapm` from `PATH` with no pin. It passes no `--cache-dir`, so
`.tlacache` lands in its working directory. How it resolves a module's path was not traced.

At `v0.0.1` it also does two things this record first listed as changes. It warns when a step passes because a
later backend closed what an earlier one failed, naming the missing `BY` tactic. And it counts a run as a success
only with no `[ERROR]` line and a non-zero count of completed obligations. Its safety tests assert both, and that
a timeout stops `tlapm`. A timeout cancels `tlapm`'s own process, not a process group.

## Decision

1. **Borrow its design, not its code or binary.** Credit it in the server's documentation. Its licence is MIT.
2. **Kept from it:**
   - `proof_check` as `tlapm --summary`: parse and count obligations without backends;
   - `prove` over one step or a line range, through `--toolbox FROM TO`;
   - reading the Toolbox protocol, not log text;
   - returning only the unresolved obligations;
   - success only with no error line and a non-zero obligation count;
   - the warnings of item 4.
3. **Changed from it:**
   - each unresolved obligation comes back with its text, the backends tried, and the reason;
   - a theorem can be named, and the server resolves the name to lines;
   - `tlapm` is the image's pinned build (ADR-0005), never whatever is on `PATH`;
   - the cache is a directory the server owns, never beside the module;
   - paths are confined to the mounted project (ADR-0008);
   - success also needs exit 0;
   - on cancel or timeout, the whole process group is killed;
   - threads, timeout stretch, and Isabelle checking of Zenon's proofs are options.
4. **Warnings on success** when a later backend closed what an earlier one failed, naming the `BY` tactic, so
   that a proof that passes by fallback is visible, as `v0.0.1` does.
5. **Compare with driving `tlapm_lsp`,** which already resolves a cursor position to its obligations, before
   building the line resolution. Take whichever is simpler and passes the same tests.
6. **`proof_results`, `flip_test` and `proof_sync` are the skill's scripts,** exposed as tools (ADR-0007).

## Consequences

- The design has been tried by someone else, and its weaknesses are already named, so Phase 4 starts from a
  short list of changes.
- The text of an obligation is what an agent needs to repair a step. Phase 4 is done when an agent using only
  these tools repairs a deliberately broken step in the fixture.
- Taking the design without the code leaves no runtime dependency on a one-person repository whose one release
  is `v0.0.1`, and none on a second language in the image.
- A success needs a non-zero obligation count. That rejects an empty or misparsed module that `tlapm` would
  otherwise pass.

## Alternatives not taken

- **Use `marco6/tlapm-mcp` as a dependency.** Its one release, `v0.0.1`, could be pinned, but the changes in item
  3 are most of the work. It would also be a second server, in a second language, beside the Python one.
- **Design from nothing.** Rule 5 is to borrow before building. The session's first answer missed this server
  entirely (C-1). This record exists so that its design is not missed a second time.
