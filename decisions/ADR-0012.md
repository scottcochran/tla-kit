# ADR-0012 — One base image; large optional tools as variants by tag, each added with a check that uses it

**Status:** Proposed · 2026.11.15
**Chosen by:** owed. `PLAN.md` D5, where the recommendation is the one recorded here. It blocks Phase 6.
**State:** Planned, Phase 6. Nothing beyond the base exists.
**Depends on:** ADR-0001, ADR-0002.
**Relates to:** ADR-0003 (the arm64 build), ADR-0005 (one prover per image).
**Pending:** the custodian's decision on D5. Also, which of cvc5, ethos and the TLA+ community modules go in the
base and which go in a variant. `PLAN.md` names Apalache and TLATeX as variants and does not place the others.

---

## Context

The custodian asked for as much of the TLA+ family as possible. Some of it is large: TLATeX needs a LaTeX
installation, and Apalache is a large tool in its own right. Neither has been measured in this image. Some of it is small and needed now: cvc5 and ethos, without
which TOPAK's certified runs (`spec/proof-cert.sh`) and the rest of `defects-run.sh` cannot run (F-7). Every tool
added is one more pin, and makes the image larger for every project that does not use it.

## Decision

1. **There is one base image.** It holds what a project needs for evidence: the checker, the prover and its
   backends, and the runtime. It is what ADR-0001 to ADR-0005 describe.
2. **Large optional tools are variants by tag,** built from the base: Apalache, and TLATeX with its LaTeX
   installation. Each variant has its own digest, and a project cites the digest it ran.
3. **Every optional tool is pinned like the rest** (ADR-0002), and is added only with a check in the self-test
   that uses it.
4. **A tool the guidance does not cover is exploratory until it does.** Apalache's type checking and symbolic
   checking are offered, and the skill gives no guidance for them yet.
5. **A second platform is a second build, not a variant.** The Linux arm64 `tlapm`, built from source, is a second
   binary and a second digest (ADR-0003).
6. **A variant is built by a switch in the `Dockerfile`, and only the variants named here are published.** The
   switch can be a build argument (`WITH_APALACHE=1`) or a named stage built with `--target`. The `Dockerfile`
   decides which, in Phase 6. The switch is how a named variant gets built. It is not a choice offered to
   users. Other combinations can be built locally, but they are not published, and their digests are not cited
   (ADR-0002 items 6 and 7).
7. **A variant only adds to the base.** No switch removes a base tool (ADR-0001 item 5).

## Consequences

- The base stays as small as evidence needs, and a project that never typesets pays nothing for LaTeX.
- A project that uses a variant cites the variant's digest. The variant's prover is the base's (ADR-0005), so
  moving the base moves every variant with it.
- More digests to publish and keep (ADR-0010). The release workflow builds the base and every variant from one tag.
- Until cvc5 and ethos are placed, `defects-run.sh` prints empty counts for its certified step. Whether it should
  say plainly that the step cannot run is a question for TOPAK (session record, §9 item 5).

## Alternatives not taken

- **One image with everything.** It is simpler to cite, but every project pulls LaTeX and Apalache, and a change to
  any tool moves every project's digest.
- **A separate image per tool.** That breaks ADR-0001's single citation. A project using two tools would cite two
  digests and keep them in step itself.
- **A switch for every tool, with any combination publishable.** Each user could build exactly the image they
  need. The number of published images would grow with every combination, and each would need a self-test of
  its own. A tag would no longer say what is inside (ADR-0002 item 6).
- **Switches that remove base tools,** for a smaller image without the prover. That reverses ADR-0001 item 5,
  and is a new record if it is wanted.
