# ADR-0020 — The claims check reports each claim in sync, stale, missing or broken, and writes nothing

**Status:** Proposed · 2026.11.20
**Chosen by:** the assistant. `COUPLING.md` §6 E3 (whole-file digests of records) is the custodian's to settle; the
record takes the recommendation.
**State:** Planned. No script and no tool exist. ADR-0023 asks for a module first.
**Depends on:** ADR-0006, ADR-0019.
**Relates to:** ADR-0007 or ADR-0022 (where the script lives), ADR-0008 (the server), ADR-0021 (CI), ADR-0023 (the
module).
**Pending:** none.

---

## Context

The skill's `proof_sync.py` tells a project whether its proof results still match its tree, in three words. Nothing
does the same for the claims a project's records make. ADR-0019 makes them data; this record is what reads them.

## Decision

1. **A script, `claims_check.py`, with the skill's other scripts:** Python 3, standard library only. It reads the
   claims table, the row lists, the newest results file of each module, and the records.
2. **It prints one line per claim, with one of four words:**
   - `IN SYNC`: the record and item exist; every named row exists with the verdict the table needs (`HOLDS` for
     `rows`, `COUNTEREXAMPLE` for `breaks`, `PROVED` for a proof); the newest results file has each as expected; and
     its module, row-list and runner digests are the tree's.
   - `STALE`: as `IN SYNC`, except that the module, the row list or the record changed after the results file was
     made.
   - `MISSING`: a record, item, module, property or row the table names does not exist, or no results file does.
   - `BROKEN`: a results file contradicts the table.
3. **A record's digest is taken whole-file,** so a History row makes its claims `STALE`. A false `STALE` costs one
   rerun; a missed one costs a claim that is no longer checked.
4. **Two checks over the whole table:** properties in a row list that are neither claimed nor marked (ADR-0019
   item 5); and claim ids in a record's text that the table lacks, or the reverse (ADR-0019 item 4).
5. **It writes nothing,** as `proof_sync` writes nothing. The server gains a fifteenth tool, `claims`, that runs it
   and returns its report as working output (ADR-0006 item 2).
6. **An `abstracted` claim is reported as such,** never as `IN SYNC`. It is not checked in TLA+, and the report says
   so.

## Consequences

- The check exits non-zero on `MISSING` and `BROKEN`, and zero on `STALE`: whether stale claims fail CI is
  ADR-0021's.
- The server's test suite gains the tool, against a fixture with one claim in each state.

## Alternatives not taken

- **Per-item record digests.** They need a parser of records; a false `STALE` is cheap.
- **A check that regenerates results.** It would be a second generator; ADR-0006 keeps results to generators.
