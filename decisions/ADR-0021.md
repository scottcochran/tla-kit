# ADR-0021 — The claims check is a required check; stale claims scope the rerun; results name the image

**Status:** Proposed · 2026.11.20
**Chosen by:** the assistant.
**State:** Planned. `ci.yml` reruns every row of both modules when `spec/` or `decisions/` changes, and has no claims
check.
**Depends on:** ADR-0014, ADR-0015, ADR-0020.
**Relates to:** ADR-0002 (item 3 of this record), ADR-0013 (item 4).
**Pending:** on acceptance, ADR-0014 item 1 and ADR-0015 item 8 each gain a History row saying that item 2 below
replaces their "every row when `spec/` or `decisions/` changes"; no other text of theirs changes.

---

## Context

CI cannot tell which rows a change reaches, so it reruns all of them on any change to `spec/` or `decisions/`. That is
affordable at two modules and is not at TOPAK's scale. And ADR-0002 item 2 says a project's results name the image's
digest; the TLC results files at `a53425b` name the jar's, in their `Checker:` line, and not the image's.

## Decision

1. **Every pull request runs the claims check** (ADR-0020), and its job is one of the required checks of `main`'s
   ruleset. It fails on `MISSING` and `BROKEN`.
2. **A `STALE` claim is rerun, and only its rows.** A pull request that changes a record reruns the rows of that
   record's claims; one that changes a module or row list reruns that module's claims. The check passes when every
   claim the pull request made stale is `IN SYNC` in the rerun. A checker pin move still reruns everything
   (ADR-0013 item 3 is unchanged).
3. **Results name the image.** The generators gain an `Image:` line, the digest `tla-kit-info` reports, when run in
   the image. The check then calls a result `STALE` if the image it names is not the one CI ran.
4. **Evidence includes the claims check of every consumer that has a table,** run in the candidate image.

## Consequences

- Item 3 changes the vendored generators; under ADR-0007 the change is made in TOPAK first, under ADR-0022 here.
- Item 3 makes every existing results file `STALE` once, and each is regenerated in the current image.

## Alternatives not taken

- **Keep rerunning everything.** Correct and simple, and it hides which claims a change touched, which is what a
  reviewer wants to see.
- **Fail on `STALE` without rerunning.** It would ask a person to regenerate what CI can.
