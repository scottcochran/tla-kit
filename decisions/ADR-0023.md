# ADR-0023 — The claims life cycle is specified in TLA+ before the check is built

**Status:** Proposed · 2026.11.20
**Chosen by:** the assistant. `COUPLING.md` §6 E5 is the custodian's to settle, as ADR-0016 item 1's form was.
**State:** Planned. No module exists.
**Depends on:** ADR-0019, ADR-0020, ADR-0021.
**Relates to:** ADR-0015, ADR-0016 (how modules are checked here).
**Pending:** none.

---

## Context

ADR-0016 wrote the `prove` tool's module before its code, and the module found the reaping question before any code
had to answer it. The claims check has a life cycle of the same size: a claim is made, a record or module changes, CI
reruns, a result is regenerated or a row breaks, and a person accepts a record.

## Decision

1. **One module, `spec/ClaimsSync.tla`,** checked as ADR-0015 item 1 says: by TLC in the image, rows in the skill's
   form, results only by the generator. TLA+ without PlusCal.
2. **It models these parties:** an author who edits records, modules and row lists; CI, which runs the check and
   reruns stale claims (ADR-0021 item 2); the generator; and a custodian who accepts a record.
3. **It states these properties:**
   - **No acceptance on a stale claim.** A record is never accepted while one of its claims is `STALE`, `MISSING` or
     `BROKEN`.
   - **A pass means a current result.** CI passes only if every claim's newest result was made from the tree CI
     checked out, in the image it names.
   - **A rerun cannot hide a break.** A row that was expected to hold and now fails is reported, and no results file
     is written over it.
4. **Its mutations are the shortcuts:** CI that skips stale claims; a generator that writes a file with a failing
   row; an acceptance that does not wait for the check; a record digest taken per item that misses a History row.
   Each breaks its property and no other.
5. **It is written after this record is accepted, and before `claims_check.py`.** Its claims go into
   `spec/claims.tsv` like the others.

## Consequences

- ADR-0020's script waits on the module.
- The module is tla-kit's third, and the first about the coupling itself, so the coupling is checked by what it
  couples.

## Alternatives not taken

- **The script first, the module after.** It would check what was built rather than what was meant (ADR-0016's
  alternatives say the same).
