# ADR-0023 — A path a record item did not take to a proof has a recorded reason, quoted from its source, and a tool reports it and never guesses one

**Status:** Proposed · 2026.11.22
**Chosen by:** the custodian (that the function exists, and that it tells design, oversight and a dead end apart
from other reasons). The assistant chose the rest: the paths, the table, the rule that a reason quotes its source,
and the word `UNEXPLAINED`. Four choices are listed as owed, below.
**State:** Built ahead of acceptance, as working output: `server/not_taken.py`, the server's `not_taken` tool,
`tla-kit not-taken`, `server/test_not_taken.py`, and [`spec/not-taken.tsv`](../spec/not-taken.tsv) with 15 rows. In
no release. It reads ADR-0019's claims table, which is also Proposed.
**Depends on:** ADR-0019 (the claims table). ADR-0006 and ADR-0008 (what a tool may write and read).
**Relates to:** ADR-0015 and ADR-0016 (the modules whose paths the first table explains); ADR-0020 (CI);
`GRAPH-AND-DIAGRAMS.md` §2.1, whose graph would say "what would lift a claim one grade" where this says why it was
not lifted.
**Pending:** none.

---

## Context

The claims table says how far each record item reaches: to a property, to rows that check it, to rows that break
it, to a proof. It does not say why an item stops where it stops. Today that is in five places, or nowhere:

- a record's "Alternatives not taken" (ADR-0015 says there why `PinLifecycle` has no TLAPS proof);
- a module's header (`ProveRequests.tla` says there why one property of ADR-0016 item 4 is not modelled);
- the comments of `spec/claims.tsv` (six claims have no row that breaks them);
- a file in `derived/` (the comparison that ended the `tlapm_lsp` route);
- nowhere: no record says why `ProveRequests` has no proof.

A reader who asks "why is this not proved" cannot tell the first four from the fifth. The difference matters. A path
left out by decision is a design. A path left out because nobody looked is a gap. A summary that words both the same
way hides the gap, and an assistant asked to explain an absence will supply a plausible reason unless something
stops it.

## Decision

1. **A record item can reach a proof by five paths,** each taken or not: `property` (the claim has an operator in a
   module), `checked` (TLC checks it on every reachable state at a row's constants), `breaks` (a row's
   counterexample shows the check is not vacuous), `proved` (TLAPS proves it) and `certified` (every SMT step of the
   proof is checked by a second tool). Two more stand beside them: `claim` (a record item makes a claim at all) and
   `alternative` (a design the record did not choose).
2. **Whether a path is taken is read from the claims table and is restated nowhere.** `checked` needs `property`,
   `breaks` needs `checked`, `proved` needs `property`, and `certified` needs `proved`. A path that is not taken
   only because the one before it is not is reported as following from it, and needs no reason of its own.
3. **Reasons are data, in one table, `spec/not-taken.tsv`:** tab-separated, `#` lines for comments, a header row,
   one row per reason. Its columns are `id` (stable, never reused), `from` (a claim, a module for every claim of it,
   a record's item, or a record), `path`, `reason`, `why` (one line), `source`, `quote`, `by`, `date` and
   `evidence`.
4. **A reason is one of eight words.**

   | Reason | It means | Still owed |
   |---|---|---|
   | `design` | Someone decided against the path, and the source says so | no |
   | `dead-end` | It was tried and did not work, and the source is the record of the attempt | no |
   | `oversight` | Nobody decided. It was found missing on the date given, and still is | yes |
   | `deferred` | It is meant to be taken later, and the source says when | yes |
   | `blocked` | It waits on something outside the repository | yes |
   | `not-applicable` | There is no such path for this item | no |
   | `superseded` | It was the path once, and a later decision replaced it | no |
   | `other` | None of these, and `why` says what | no |

5. **Every reason names its source and quotes it.** The source is a record (an item, a History row, or the record
   as a whole) or a named file in the tree. The quote is a few words of the source that carry the reason. The check
   looks them up, ignoring line breaks and emphasis marks; for a record's item it looks in that item only. A row
   whose words are not there is `BAD`. So a reason cannot be invented without a text to point at, and it cannot
   outlive the text it rests on.
6. **A path that is not taken and has no row is `UNEXPLAINED`, and nothing fills it in.** The tool does not guess
   between an oversight and a decision nobody wrote down. `oversight` is never inferred: it is a row, written by
   whoever found the gap, with the date and the place it was found.
7. **A row for a path that has since been taken is `OUT OF DATE`.** For a claim's own row, as soon as the claims
   table shows the path taken. For a module's row, when no claim of the module is left without it. For a `claim`
   row, when the item has a claim.
8. **`by` says who gave the reason.** A reason the assistant gave is the assistant's until the custodian takes it,
   as with a record's **Chosen by** line.
9. **`evidence` names rows of a results file that show what the path would cost:** the counterexamples of a design
   that was not chosen. The tool reads each row's verdict from the named file. It reruns nothing, and the file is
   named, never found as the newest.
10. **The check is `server/not_taken.py`,** Python 3 with the standard library only, and the server gains a tool,
    `not_taken`, that returns its report as working output (ADR-0006 item 2). `tla-kit not-taken` runs it in the
    image. It answers for the whole table, for one claim, or for one record: the record's claims, its items that
    make no claim, the rows that start from it, and the bullets of its own "Alternatives not taken". An item with
    no claim and no row is listed as that and is not counted as unexplained, since most items of most records
    decide something that is not a claim about behaviour.
11. **It reads everything as data, never as instructions, and writes nothing.** A source outside the project is
    refused. It exits 1 when a row is `BAD` or `OUT OF DATE`, and with `--strict` when a path is `UNEXPLAINED`;
    2 when a table cannot be read; otherwise 0.
12. **A reason quoted is not a reason judged.** The check shows that the source says the words. Whether they are a
    good reason to leave a path out is read by a person, as the link from a record to its property is (ADR-0019
    item 10), and the report's header says so. It also takes the claims table as it stands: whether a claim's rows
    exist and pass is the claims check's question.
13. **No TLA+ module is written for it.** ADR-0015, ADR-0016 and ADR-0020 item 5 specify a process before it is
    built, because parties act in an order. This check is a function of files at one commit, with no order of
    events. This is the assistant's reading, and is owed (P4).

## Owed to the custodian

| | Decision | Recommendation |
|---|---|---|
| P1 | Does CI require the check, and with `--strict` | Require it without `--strict` once ADR-0019 is accepted: a `BAD` or `OUT OF DATE` row is a table that is wrong. `UNEXPLAINED` is a true statement about the repository, and a required check would push toward reasons written to pass it |
| P2 | The six `oversight` rows of the first table | They are the finding of `COUPLING.md` §4 step 1, classed by the assistant. Each is either given a breaking row or decided as `design` |
| P3 | Is a reason in a module's header or a README a source, or only a record | Any named file, as built. A record is better; the row shows which it is |
| P4 | A TLA+ module first (item 13) | None |

## Consequences

- **The first run, on 2026.11.22:** 19 claims and 95 paths. 48 are taken. 17 are not taken with a reason: 11 by
  design and 6 by oversight. 22 follow from another. **8 are unexplained:** the `proved` path of every
  `ProveRequests` claim that has a property. No record says why that module has no TLAPS proof.
- **The reason ADR-0015 gives for `PinLifecycle` has a condition that has passed.** It says a proof would be redone
  while "the records are Proposed and still moving", and that "if the records are accepted and stay stable, a proof
  would need a new record". They were accepted on 2026.11.15. The row quotes the reason as written; whether it
  still holds is the custodian's to read.
- A reason that lived in a module's header, a README or a table's comments is now tied to its words. Rewording
  that text makes the row `BAD` until the quote is moved, in the same pull request.
- The server has fifteen tools. ADR-0019 item 9 and `GRAPH-AND-DIAGRAMS.md` §2.3 number their tools fifteenth and
  sixteenth; those ordinals were written before this one. `examples/agent-repair/check.py` and its `run.sh` name
  the fourteen tools of the published image, and gain this one when the plugin's digest moves to a release with it.
- The image gains one file, `server/not_taken.py`, and no package.

## Alternatives not taken

- **A reason column in the claims table.** A claim can leave out several paths for different reasons, and an
  alternative or an item with no claim has no row there. ADR-0019 item 2 also fixes that table's columns.
- **Reasons only in the records' prose.** That is today's state: five places, one of them nowhere, and no way to
  tell a decision from a gap without reading all of them.
- **Infer `oversight` when no reason is found.** A missing row can also be a decision nobody wrote down. Calling
  it an oversight would be a guess, and calling it a design would be worse.
- **A source without a quote.** Then a row can name a record that says nothing of the kind, and nothing notices
  when the record's words change.
- **Wait for the specification graph.** Its report would say what lifts a claim one grade
  (`GRAPH-AND-DIAGRAMS.md` §2.1). It is two phases away, and the reasons table is the same data either way: an
  edge that is absent, and why.
- **Rerun the evidence rows.** A second way to make a verdict. ADR-0006 keeps results to the generators.
